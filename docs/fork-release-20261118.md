# 2026-11-18 fork 修复版

本分支基于 `WGooold/Orbis` 的 `8b087de919064db0f5419ca6e8215fc5957919be`，包含 Host 连接延迟修复、原生 Claude Code 忙时消息投递，以及 iOS 聊天和附件界面修复。

## 使用前

- iOS 的忙时发送需要同时更新 Host 和 Claude 插件；正在运行的旧 CC 会话需在任务结束后重新打开或恢复。
- 忙时消息通过原生 Mods 的 `turn.abort` 停止当前前台执行，再用 `prompt.submit(asUser: true)` 在同一会话继续。上下文保留；当前工具或请求会中断。
- 仍由原生 Claude Code TUI 执行，没有改为 Agent SDK，也不模拟键盘输入。权限模式继续读取 Claude Code 自己的设置。
- IPA 未签名，需要侧载工具为主 App、Live Activity 和通知扩展一起签名。改变签名身份或 Bundle ID 可能影响覆盖安装与推送。
- APK 使用 fork 自己的发布证书，不能直接覆盖官方证书签名的安装。发布私钥不在仓库或 Release 中。
- Android 和 iOS 使用各自的原生界面实现。本分支分别补齐忙时默认插话、接收状态、照片入口和历史提示避让；文件选择器的初始目录按各自系统提供方处理。

## 改动

- compact 状态请求提前停止 legacy bootstrap；同一进程内保留协商结果，减少重连后重复菜单传输。
- 独立后端并行读取会话目录；Codex 的用量、运行状态等临时更新不再无条件触发目录重扫。
- Host 保留消息的 `steer` / `followUp` 意图，并按原生插件能力决定是否允许插话。
- 原生提交结果返回后才报告成功；断连导致结果未知时报告 `unconfirmed`，避免普通重发重复执行。
- iOS 忙时默认插话；重发保留投递意图，区分“发送中”和“电脑已接收，等待处理”。
- iOS 最近提问提示避让历史按钮，保留历史阅读位置；附件增加照片入口，文件选择器默认请求 App 文档目录。
- Android 忙时默认插话、重发保留投递意图；接收状态与发送状态分开显示。忙时发送复用完整的附件交接，避免丢失附件路径。
- Android 增加系统照片选择入口，文件选择器初始请求本机 Documents；历史状态行可见时隐藏最近提问浮层，保留“更早的消息”按钮。

## 已有验证与边界

原生 Claude Code 2.1.318 TUI 配合隔离本地受控上游，已验证普通输入框、本机已有草稿和空白 Shell 输入模式。三种情况都提交为用户消息，本机草稿保留。电脑端排队至下一次模型请求约为 104 / 133 / 700ms；这不是手机外网端到端耗时，也不是官方上游风控验证。

本批相关 TypeScript、Mods、Host 测试和 iOS 附件、等待发送、界面检查已通过。真实手机外网发送总耗时、签名后的 APNs、真机照片选择至完整上传仍需设备验收。

## 构建

在本分支提交的独立检出目录构建，输出放在源码目录之外。iOS 使用 Xcode 27.2，Release、`generic/platform=iOS`、`CODE_SIGNING_ALLOWED=NO`、`CODE_SIGNING_REQUIRED=NO`，本次目标／历史修复包构建号为 `2026111804`，将主 App 连同两个内嵌扩展放入 `Payload/` 后打包。

Android 使用项目已有 Gradle Wrapper 和 `:app:assembleRelease`，签名属性名及配置方式见 `android/app/build.gradle.kts`。需要 JDK 17、Android SDK 35，以及项目原生 QUIC 构建所需的 Go / NDK。凭据应放在构建环境或用户私有配置目录，不能加入提交。

Release 的 IPA 为 iOS 17+ / arm64 包；APK 的最低版本和 ABI 以最终发布说明列出的包检查结果为准。

## 后续修复：目标控制与长会话历史

- Codex／Codex Desktop 新增原生目标查看、编辑、暂停和恢复入口，通过 `thread/goal/*` 操作原有目标。不会向聊天记录追加控制消息，不改变模型或供应商配置。原生端不支持该接口时，会隐藏入口并说明需要更新。
- Codex 历史重建保留同一运行期的来源 epoch，继续递增 seq；清理重建前的分页缓存并拒绝迟到旧页，避免长会话耗尽退役 epoch 记录后持续同步失败。保留原有上限和旧状态拒绝保护。
- Claude 后台任务完成通知改为简短的系统状态，避免将内部 XML 显示为用户输入；用户自己发送的 XML 保持原样。
- 插话能力缺失时明确提示旧窗口需要在本轮结束后执行 `/reload-plugins`；这项提示不会给已加载的旧插件增加能力。
- 历史同步失败使用对应提示，避免误认为消息发送失败。

相关 Host／协议测试、iOS 核心目标与发送测试、Android 目标与发送测试已通过；iOS 模拟器已验证目标读取、编辑、暂停和恢复。未使用生产目标做写入验收。IPA 仍需侧载签名；Android 包继续使用 fork 发布证书。

## 后续电脑端修复：Claude 进度与正文同步

- 原生短摘要按 Claude Code 的逐段标记识别；普通思考继续保留为可折叠的思考内容，不根据全局显示偏好展开。
- Bash 的任务说明单独显示为简短状态行，执行中的实时说明与原生历史使用同一工具调用 ID，交接后不重复显示。命令正文仍保留在工具详情中。
- Host 重启后错过轮次开始、原生追加通知先于文件落盘时，按消息 UUID 限时补读，并处理后续完成通知。旧轮次的完成和补读不会清理新轮次内容。
- Host 在流式输出中途重建时，已确认的新连接改从原生历史接收当前正文，避免旧连接的身份预约产生内部警告；保留源的重连继续使用原有实时交接。
- 明确拒绝的手机消息不再关联之后在电脑输入的同文消息，也不会自动重发。

这批修复需要更新电脑端 Host／Claude 插件；`fork-20261118.3` 的 IPA／APK 已包含所需手机界面，无需为这些显示改动重新安装。相关 Host 测试、类型检查及真实 Claude Code 2.1.318 配合 localhost 受控上游验证通过：工具运行时可见任务说明，Host 在工具执行中重建后，最终正文无需第二条用户消息即可同步；手机已确认短说明与最后正文可见。

Claude Code 的电脑端 Esc／Stop 会阻止插件发起新工作，直到下一次电脑端用户输入。Orbis 会明确显示这类拒绝并保留失败状态；不能靠重试、等待完成通知或 `asUser` 参数解除。Orbis 的停止按钮调用原生 Mods `turn.abort`，其行为与电脑 Esc 不同。上述边界对应 Claude Code 2.1.318 的公开 Mods API，不涉及 SDK 或上游代理配置修改。
